# T1 Vision Foundations

Status: T1 accepted foundation note.

This note records the minimum computer-vision concepts needed before VisionLab starts its dataset contract and model work. It is intentionally small: T1 should build evaluation judgment, not a hidden training pipeline.

## Image Tensors

An image classifier receives numbers, not a photograph.

Common image tensor layouts:

- `H x W`: grayscale image without an explicit channel dimension.
- `H x W x C`: common image-library layout, where RGB has `C = 3`.
- `C x H x W`: common PyTorch model layout.
- `N x C x H x W`: a batch of `N` images for model input.

Important checks:

- dtype: integer pixels and floating-point tensors behave differently;
- range: `0-255`, `0.0-1.0`, and normalized values are different contracts;
- channel order: RGB and BGR swaps can silently damage learning;
- spatial size: resizing can remove details or distort class evidence.

## Normalization

Normalization changes numeric scale so optimization is better behaved and pretrained models receive the format they expect.

For a custom CNN, VisionLab can choose and document a simple normalization profile. For a pretrained model, VisionLab must use the preprocessing expected by the selected weight identity. Training, evaluation, and inference should share the same registered preprocessing source of truth.

## Convolution

A convolution kernel slides over local neighborhoods and produces a feature map. In CNN libraries, the operation is often implemented as cross-correlation: the kernel is applied without flipping. That distinction rarely changes the learning concept because the model learns kernel values, but it matters when hand-checking tiny examples.

Important controls:

- kernel size determines the local pattern being measured;
- stride controls how far the kernel moves each step;
- padding controls whether borders are retained;
- output shape depends on input size, kernel size, stride, and padding.

T1 includes a dependency-light edge-kernel demo generated by `scripts/make_t1_foundation_artifacts.ps1`.

## Pooling

Pooling compresses spatial dimensions. Max pooling preserves strong activations in a window; average pooling preserves a local mean. Pooling can improve translation tolerance, but it also discards location detail.

## Feature Maps

A feature map is an activation image produced by applying a kernel or learned filter. Early CNN feature maps often respond to edges, color contrasts, and simple textures. Later feature maps combine earlier evidence into larger patterns.

Feature maps are diagnostic signals, not proof that a model understands an image.

## Receptive Field

The receptive field is the region of the original image that can influence one later activation. Stacking convolution and pooling layers increases the receptive field. A compact custom CNN must preserve enough spatial information for the classes it is asked to separate.

## Data Splits

VisionLab should preserve clear roles:

- training data updates model parameters;
- validation data supports development choices and checkpoint selection;
- test data estimates performance after development choices;
- OOD or cross-source data measures distribution shift and should not guide routine tuning;
- real-world evaluation data remains protected during applied-domain work.

T1 does not create a dataset contract. It only recommends a provisional development dataset for Phase 1 review.

## T1 Builder Check

Before Phase 1, the builder should be able to explain:

- how an RGB image becomes a `C x H x W` tensor;
- why dtype and range checks matter;
- what a convolution kernel produces;
- how stride, padding, and pooling change feature-map size;
- why validation and test data should not serve the same role.
